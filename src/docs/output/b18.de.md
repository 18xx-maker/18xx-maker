# Board18-Ausgabe

## Anwendung

In der Anwendung hat der Export-Button einen Eintrag, um das Spiel als
Board18-Box zu exportieren, und im Panel _Exportoptionen_ kannst du die Version
und den Autor festlegen. Sie starten mit `exports.b18` aus der Spieldatei (siehe
[Exportoptionen](/docs/games/exports)). Du wirst nach einem Ordner gefragt, in
dem die Zip-Datei und die darin enthaltenen Dateien (der unten beschriebene
Aufbau) abgelegt werden. Die Bilder einer Box haben einen Pixel pro Einheit,
unabhängig von der Auflösung, die du für PNG-Bilder wählst.

## Kommandozeile

> [!IMPORTANT]
> Dieser Ablauf setzt voraus, dass du den Quellcode der App hast und den
> Anweisungen zur [lokalen
> Entwicklung](https://github.com/18xx-maker/18xx-maker/blob/main/DEVELOPMENT.md)
> gefolgt bist.

Du kannst eine Zip-Datei für Board18 erzeugen, indem du Folgendes ausführst:

```bash
pnpm build && pnpm maker export <game> --format b18 --b18-version <version> --b18-author <author>
```

Dabei ist `<game>` das Spiel, das gebaut werden soll (die ID eines
mitgelieferten Spiels oder der Pfad zu einer Spieldatei), `<version>` ein
Versions-Tag für Board18 und `<author>` der Autorenname für Board18. Hier zum
Beispiel baue ich 1889:

```bash
pnpm build && pnpm maker export 1889 --format b18 --b18-version CGG01 --b18-author "Christopher Giroir"
```

`pnpm maker b18 1889 CGG01 "Christopher Giroir"` macht dasselbe. Wenn du
`--b18-version` und `--b18-author` weglässt, kommen die Werte aus `b18` im Feld
`exports` der Spieldatei, zum Beispiel `"exports": { "b18": { "version":
"CGG01", "author": "Christopher Giroir" } }`, danach aus `b18.author` von
`maker config`, und danach sind es `1.0` und dein Name. Ein Flag hat immer
Vorrang vor der Spieldatei, genauso wie das, was du im Panel eingibst. `pnpm
maker b18 my-game.json` ohne Version übernimmt sie aus der Spieldatei. Die
Bilder einer Box haben einen Pixel pro Einheit (die Größe, die Board18
erwartet), sie werden nicht durch `--dpi` skaliert. Karte und Aktienmarkt sind
immer weiß, Token und Plättchen transparent, `--background` ändert daran
nichts. Mit `--variation <n>` baust du die Box einer anderen Kartenvariante.

Denk daran, dass dabei die Einstellungen aus dem Konfigurationsbereich im
Browser nicht verwendet werden. Damit deine gedruckte Ausgabe mit dem
übereinstimmt, was du im Browser siehst, öffne das Panel
[Konfiguration](?config=true) und speichere mit „Download config.json“ eine
Datei, und füge dann `--config my-config.json` zum obigen Befehl hinzu.

Dadurch wird die App gebaut und anschließend die Datei
`render/1889/board18-1889-CGG01.zip` sowie eine Reihe weiterer Dateien erzeugt:

```
render/1889
├── board18-1889-CGG01
│   ├── 1889-CGG01
│   │   ├── Brown.png
│   │   ├── Green.png
│   │   ├── Map.png
│   │   ├── Market.png
│   │   ├── Tokens.png
│   │   └── Yellow.png
│   └── 1889-CGG01.json
└── board18-1889-CGG01.zip
```

Wenn die CLI sich deinen Autorennamen merken soll, damit du ihn nicht jedes Mal
eintippen musst (für alle Spiele, die keinen eigenen festlegen), kannst du
Folgendes ausführen:

```
pnpm maker config set b18.author "<Your Name>"
```
