# 文件

18xx Maker 使用了许多不同的浏览器技术来处理文件,这可能会让人困惑。本页将帮助您理清其中的情况。

## 内置游戏

18xx Maker 的应用和网页中预先打包了许多 json 文件。例如 [Shikoku 1889](/games/1889/map) 和 [The Old Prince 1871](/games/TheOldPrince1871/map)。这些游戏始终列在[加载游戏](/games)页面上。您可以通过游戏信息页面上的“下载”(网站)或“保存”(应用)按钮下载 json,了解这些游戏是如何构建的。若要保留一份可以编辑和保存的副本,请使用游戏菜单(或“更改”页面)中的“另存为...”:它会询问文件名,保存游戏当前状态的副本并打开该副本。内置游戏本身不会改变。

若要检查游戏文件是否有错误,请运行 `pnpm maker validate my-game.json`(它会根据游戏模式校验文件,参见 [JSON 模式](/docs/games/schemas))。所有命令见[命令行](/docs/output/cli)页面,保存在您设备上的设置见[配置面板](/docs/config)和[桌面应用](/docs/app)页面。

## 使用 18xx Maker 应用

使用应用时,18xx Maker 可以访问您的文件系统,这意味着您可以从电脑加载 JSON 文件。您可以通过几种方式打开游戏文件:

1. 使用“打开”菜单选项,并选择一个有效的 JSON 文件
1. 在应用中的任意位置按“o”键
1. 点击[加载游戏](/games)页面上的“打开文件”按钮。
1. 将有效的 JSON 文件拖入应用窗口

想从头开始,请点击[加载游戏](/games)页面上的“新建游戏”按钮。应用会询问新游戏的保存位置,在那里写入一个小游戏(一个标题和一块 4 × 4 的六边形),并在地图上打开它,可以直接编辑。新文件会像你打开的任何游戏一样出现在列表中。

无论哪种方式,应用都会把该文件的位置保存在其记忆中,然后显示游戏。此后您会在[加载游戏](/games)页面上看到该文件。此页面上的垃圾桶图标**不会**删除文件,而是删除应用对该文件的记忆,该条目会从页面上消失。

如果您在电脑上移动了文件,然后试图点击[加载游戏](/games)页面上的条目来加载它,应用会告知您找不到该游戏,并从页面上移除该条目。

加载游戏后(无论通过上述哪种打开方式,或点击之前打开过的文件的条目),应用会从文件系统加载最新版本,并开始监视该文件。所做的任何更改都应几乎即时地反映在应用中。

## 使用 18xx Maker 网站

网站版 18xx Maker 的行为会因您的浏览器是否支持[文件系统 API](https://developer.mozilla.org/zh-CN/docs/Web/API/File_System_API) 而略有不同。

### 支持的浏览器

您可以通过几种方式从电脑加载文件:

1. 在应用中的任意位置按“o”键
1. 点击[加载游戏](/games)页面上的“打开文件”按钮。
1. 将有效的 JSON 文件拖入浏览器窗口

想从头开始,请点击[加载游戏](/games)页面上的“新建游戏”按钮。浏览器会询问新游戏的保存位置,在那里写入一个小游戏(一个标题和一块 4 × 4 的六边形),并在地图上打开它,可以直接编辑。新文件会像你打开的任何游戏一样出现在列表中。无法以这种方式保存文件的浏览器(见下文)则会把新游戏保存在源私有文件系统中。

无论哪种方式,浏览器都会把该文件的位置保存在其记忆中,然后显示游戏。此后您会在[加载游戏](/games)页面上看到该文件。此页面上的垃圾桶图标**不会**删除文件,而是删除浏览器对该文件的记忆,该条目会从页面上消失。

以后再次访问该网页时,当您尝试从[加载游戏](/games)页面加载其中某个游戏,浏览器可能会向您请求权限。如果您不授予该文件的权限,它将从此页面移除,但您始终可以通过上述任一方式再次打开它。

如果您在电脑上移动了文件,然后试图点击[加载游戏](/games)页面上的条目来加载它,网页会告知您找不到该游戏,并从页面上移除该条目。

浏览器无法监视文件的变化。以这种方式加载文件后,工具栏中会出现“刷新”选项。点击它应当会用本地对文件所做的更改刷新网页。在已从文件系统加载游戏时,您也可以在应用中的任意位置按“r”键刷新。

### 不支持的浏览器

即使您的浏览器不支持文件系统 API,我们也会尝试改用[源私有文件系统](https://developer.mozilla.org/zh-CN/docs/Web/API/File_System_API/Origin_private_file_system)。您可以通过以下两种方式之一打开文件:

1. 点击[加载游戏](/games)页面上的“打开文件”按钮。
1. 将有效的 JSON 文件拖入浏览器窗口

[加载游戏](/games)页面上的“新建游戏”按钮会在这个独立的位置创建一个小游戏(一个标题和一块 4 × 4 的六边形),并在地图上打开它,可以直接编辑。使用游戏页面上的“下载”按钮可以获得文件副本。

这样做之后,该文件的内容会保存在您本地电脑上一个只有浏览器才能查看的独立位置。游戏会出现在[加载游戏](/games)页面上。点击此页面上的垃圾桶图标**不会**从您的电脑上删除文件,而是让浏览器忘记这个游戏。

要从电脑上的数据刷新文件,唯一的办法是使用上述任一方式重新打开它。

## 导入 config.json

你在[配置面板](?config=true)中更改的设置可以在“数据”部分保存为 `config.json`。要在其他地方应用这样的文件,可以把它拖到应用或网站上,或把内容粘贴到“数据”部分的导入框中。导入的设置将替换你当前的自定义设置。如果拖入的 JSON 文件只包含配置设置,它会被当作配置处理,否则会作为游戏加载。

## 编辑游戏信息

在游戏的编辑页面上,工具栏中的“编辑”按钮(或 `e` 键)会在页面旁打开一个面板,其中有游戏信息、链接以及原型和制作中标记的表单。页面保持可见,并随你的输入而更新。该表单由[游戏文件模式](/docs/games/schemas)生成,因此模式中这些部分新增的字段会直接出现在面板中,无需修改应用。字段名称和说明来自模式,仅提供英文。离开字段或按回车键时,值会被应用;清空字段会将其从游戏中移除(标题不能被移除)。值的问题,例如缺少 `#` 的货币,会显示在字段下方。按 Escape 关闭面板(JSON 编辑器见下文)。

表单上方有一个搜索框,可按名称查找当前分区中的字段(按 `/` 聚焦)。Enter 跳到下一个匹配,展开其所在的卡片,滚动到该字段并高亮标记,焦点仍留在搜索框,因此再按 Enter 会继续跳到下一个;Shift+Enter 跳到上一个,Alt+Enter 聚焦当前匹配的字段,Esc 清除文本。搜索不会查看卡片中已折叠的“更多字段”部分。在列车、私有公司和公司标签页中,卡片上方的筛选框会把卡片缩小到名称、缩写、标题或备注包含所输入文本的那些。筛选只是隐藏卡片,不会更改游戏,添加条目会清除筛选。

面板为它编辑的游戏的每个部分提供一个分区,以芯片形式显示在“游戏”“配件”和“外观与输出”三个分组下。标题栏中的“表单 | JSON | 问题”开关在这些表单、JSON 编辑器(见下文)与游戏的问题列表之间切换,“表单”会回到你上次所在的表单。“问题”上的红点表示游戏有问题;点击其中一个问题,会在 JSON 编辑器中打开它所在的行。按 `[` 和 `]` 在表单分区之间切换(在 JSON 编辑器或问题列表中会跳到上次的表单;数字键会跳转到游戏的其他部分并保持面板打开)。芯片上的红点表示该分区有问题,其标签会说明数量。更改会保留在内存中,直到你用表单下方的“查看并保存更改”按钮保存。列车标签页为游戏的每辆列车提供一张卡片,由同一份模式生成。用“添加列车”添加列车,并用卡片上的按钮上移、下移、复制或删除它。删除后可以立即用“撤销”恢复。不常用的列车字段在“更多字段”下。模式中标记为已弃用的字段仍可编辑,并会显示警告。

私有公司标签页以同样的方式编辑游戏的私有公司。卡片首先显示名称、价格、收益和公司。收益是一个数字,或按打印方式书写的列表,如 `10/20`;不是数字的文本(如 `$10/$20`)保持为文本。其他字段(如备注和说明)在“更多字段”下。

公司标签页以同样的方式编辑游戏的公司。由于公司有很多字段,它的卡片一开始是折叠的,并显示颜色、名称和缩写;点击标题即可展开。折叠的卡片在内部有问题时会显示警告标记。名称、缩写、颜色和 minor 标记首先显示,其他字段(如标志和执照文字)在“更多字段”下。股份、标记、列车、贷款及类似字段以 JSON 编辑。公司需要名称和缩写,且不能清空。新公司会得到一个未被使用的缩写,副本会在来源的缩写后加上数字(PRR 变为 PRR2)。游戏的其他部分(如股市)通过缩写引用公司:重命名时,面板不会更新这些引用。

阶段标签页以同样的方式编辑游戏的阶段。卡片首先显示名称、限制、地块、列车、minor 标记和回合数;公司、阶段开始的事件、备注、购买公司和事件在“更多字段”下。限制是一个整数、`∞` 或类似 `3/4` 的分数。列车和备注是文本,每行写一项时则是列表(单独一行保存为普通文本)。阶段需要限制和地块(不能清空),以及名称或列车。两者都没有的阶段会显示模式的提示:几个选项中必须符合一个。在阶段没有名称的游戏中,新阶段会得到列车而不是名称。阶段开始的事件(`on`)以 JSON 编辑,因此列车名称要带引号,如 `"3"`。名称是游戏的其他部分引用阶段或列车的方式:重命名时,面板不会更新这些引用。

市场标签页编辑股票市场:类型(2D、1D 或 1Diag)、单元格网格、单元格默认值、图例和移动。点击单元格,或用方向键移动,即可在网格下方的表单中编辑它:数值、标签、颜色、图例项、发行价标记、箭头等。Delete 清空单元格,数字键跳到其数值。网格上方的按钮可为所选单元格所在的行或列添加、移动、复制和删除;删除的行或列可用“撤销”恢复。市场常常是三角形,因此各行长度可以不同,且不会被补齐。1Diag 市场分两行绘制,一列是两个单元格。只有数值或只有标签的单元格会保存为该数字或文字,设置第二个字段后才变成对象。把类型改为 1D 或 1Diag 时只保留第一行,并可撤销。图例项按编号使用:移动或删除某一项时会显示有多少单元格现在指向另一项,它们的编号不会被修改。显示、ledges、limits 和标题是“高级”下的 JSON 字段。

玩家标签页编辑游戏的银行、资本和证书上限、公司需要卖出多少百分比才会启动,以及玩家表:每个玩家人数一张卡片,标题形如“3 名玩家”,首先显示编号、资本和证书上限,银行在“更多字段”下。银行、资本和证书上限是数字或文本:数字保存为数字,`∞` 或 `3/4` 这样的文本保持为文本。“添加玩家”会使用下一个编号,复制也会得到下一个空闲编号。玩家需要编号,不能清空。编号不会被排序,也不会检查重复:问题检查会报告模式不允许的内容。

回合标签页编辑回合追踪器的回合(每个回合标记一张卡片,首先显示名称和颜色,其他标记字段在“更多字段”下)、印在公司卡上的行动(名称、步骤、步骤是否编号以及可选步骤)以及数字卡的颜色。

标记标签页编辑标记页上的标记、标记类型和股份类型。一个标记是一行文本或数字(白色标记的标签),或者用“添加带选项的标记”添加一张卡片,首先显示标签、图标、徽标和颜色,其他标记字段在“更多字段”下。标记类型以同样方式列出公司卡上的标记位置(费用,以及公司是否以标记开始),股份类型列出它的股份(首先显示数量、标签、百分比和费用)。重命名或删除某个类型时,编辑器会警告有多少家公司仍以旧名称使用它。

公司的标记和私有公司的标记(在“更多字段”下),以及标记标签页中的每个标记,都有一个“编辑标记”按钮,会在对话框中打开标记编辑器。预览按打印效果显示标记,可选浅色或深色背景,每次更改都会立即写入游戏:无需保存,“重置”会恢复为打开对话框时的标记。形状、内容(标志、图标和标签)、颜色和装饰(横条、条纹、盾牌、两半等,各有自己的选项)分组显示,其他所有属性在“高级”下。需要颜色的形状可以是颜色或 true(白色),有多种颜色的(如两半)每种颜色各有一个字段。标记列表中只有标签的标记仍保持为文本或数字。编辑器不认识的内容会保留在标记中。

颜色标签页编辑游戏中按名称命名的颜色。每种颜色都有一个可打开取色器的色块,以及一个可输入任何 CSS 颜色或另一种颜色名称的文本框;“添加颜色”会新增一种颜色,名称字段可用于重命名或删除。随阶段变化的颜色是一个对象,仍以 JSON 编辑。

输出标签页编辑收益图表的范围(第一个和最后一个收益,以及每行的数量)、游戏的导出默认值(文件、页面、布局、背景、变体,以及 PNG、卡牌和 Board18 选项)。已弃用的导出选项 paginated 不会显示,仍保留在文件中。

地图标签页在每个页面上都有(在其他页面上点击它会转到地图页面),编辑所选地图变体(`?variation=`)除六边格之外的全部内容:名称、它复制哪个变体(变体列表时;复制来的六边格可按坐标移除,每行一个)、是否隐藏标题、被裁切的边、回合追踪器、移动、市场和玩家的位置,以及边界、线条和边界文字(每项一张卡片,坐标每行一个)。复制了其他变体的变体,其边界、线条、边界文字和裁切是被复制变体的加上自己的。六边格本身由六边格标签页编辑。

地图标签页的开头有四个箭头按钮“移动地图”,可将整个游戏移动一行或一列:所有地图变体的每个六边格、边界、线条和边界文字,以及公司和私有公司中引用六边格的 `home`、`destination` 和 `hex`。向上和向下改变字母,向左和向右改变数字(横向地图则相反)。当六边格、被移除的六边格、边界、线条或边界文字已在第一行(A)或第一列(1)时,按钮会被禁用;会离开地图的引用保持不变,看起来像坐标的标记标签也一样。以像素为单位的位置(回合追踪器、移动、市场和玩家)不会被移动。向右或向下移动会使未裁切的地图变大,被裁切的边仍保持裁切。移动一格会改变哪些六边格朝上(`a1Valid`),Board18 导出会随之变化。一次移动是更改列表中的一步,还原可以撤销它。

六边格标签页在每个页面上也都有(点击它会转到地图页面)。点击地图上的六边格即可选中它所在的组,也就是 `map.hexes` 中列出它的那一项:标签页随后只显示该组,默认是表单,也可以用“表单/JSON”开关切换为 JSON,组内的六边格会在地图上被描出轮廓。表单像地图一样绘制六边格,每条边上有一个按钮:点击两条边即可绘制它们之间的轨道,从列表或图中选取元素来编辑其字段,还可以添加、复制、移动或移除元素。拖动城市、城镇、标签或其他元素即可移动它(改变其 `x` 和 `y`),并可用按钮或 Ctrl 或 Cmd+Z、Ctrl 或 Cmd+Shift+Z 撤销或重做更改;一次拖动算一步,每个六边格的历史都会重新开始,切换到 JSON 视图再切回时也会重新开始。焦点在字段中时,快捷键不起作用。表单只写入你更改的内容。JSON 文本无效时无法离开 JSON 视图。当更改会影响该组的多个六边格,或另一个组也列出了该六边格时,会有提示。空位置也可以选中,地图之外紧邻的一行和一列也可以。只要文本是有效的组,页面就会随之更新,有效的组是带有 `hexes` 列表的对象,列表至少有一个类似 `B2` 的坐标;其他内容只是草稿,游戏保持上一个有效版本。按住 Cmd(Windows 和 Linux 上为 Ctrl)并点击另一个六边格,可将它移入该组(并移出原来所在的组),点击该组内的六边格则将其移出。没有六边格的组会被移除,地图的最后一个六边格会保留。空位置的组在你第一次修改它时才会添加到游戏中。按 Escape 取消选中该组。地址以 `hex` 记录它,即该组的第一个坐标(`?edit=true&editSection=hex&hex=C11`)。选取六边格只在屏幕上可平移和缩放的地图、且面板打开时有效,打印和导出的地图不会改变。复制了另一个地图的地图变体会显示复制来的六边格:请在它们来源的变体中修改,或点击“在此覆盖”,在此变体中复制该六边格并编辑副本。表单的边按钮和列表都可以用键盘操作。每个元素都有自己的字段,按钮“仅编辑 C11”(带有该六边格的坐标)会为多个六边格的组中的一个六边格建立该组的独立副本,使更改只对该六边格有效。见[六边格编辑器](/docs/games/hex-editor)。

地块标签页在每个页面上都有(在其他页面上点击它会转到地块页面),编辑游戏的 `tiles`。它按文件中的顺序列出地块。输入编号并点击“添加地块”即可添加:18xx Maker 已知地块的编号会按原样添加(数量为 1),其他编号则开始一个你自己的地块,随后由你绘制。在列表中选择一个地块即可编辑它(地址以 `tile` 记录它,例如 `26|T2` 为 `?tile=26%257CT2`)。在地块表上也可以点击地块来选中它(它的所有副本都会被描出轮廓),点击最后一个地块之后的虚线 + 格或地块表上任何其他空位可添加新地块(`T1`、`T2`……)并选中它;这只在编辑面板打开时有效,打印的地块表不会改变。你自己的地块像地图的六边格一样编辑,按地块表的方式绘制,并带有数量、打印数量和分组。从库中绘制的地块,即单纯的数量、另一地块的别名或库中地块的部分修改,会按绘制的样子显示,只能修改它的数量、打印数量和分组;库本身从不被编辑。点击“自定义”可把库中的地块作为你自己的地块复制到游戏中,再编辑它。只修改单纯数量的数量时,它仍然是一个数字,也不会添加你没有更改的字段。数量是带箭头的数字框,并有一个“无限”开关。“复制地块”会在该地块之后添加一个副本,“移除地块”将其移除(移除最后一个时会去掉 `tiles`),“重命名”会改为另一个编号(列表顺序保持不变,但纯整数编号总是排在最前面),并同步到绘制它的私有公司中。从库中绘制的地块只能改变编号中 `|` 之后的部分,因为编号是找到库中地块的依据:请先自定义,才能随意重命名。地块不在地图上,所以这些操作都不会改变地图。

配置标签页以 JSON 编辑游戏的 `config`,即在[配置面板](/docs/config)中开启“允许游戏配置”时对该游戏生效的设置。它是一个对象,例如 `{ "fonts": { "roles": { "title": { "style": "italic" } } } }`。只要文本是 JSON 对象,页面就会随之更新;其他内容只是草稿。[配置模式](/docs/games/schemas)不允许的值(例如字体的 `size` 为 `"big"`)会在文本中标出,并在标签页上显示红点。清空对象会从游戏中移除 `config`。

编辑内容保留在已加载的游戏中。请在下文所述的“更改”页面查看并保存。

### JSON 编辑器

JSON 编辑器以 JSON 编辑整个游戏(与“下载”按钮写入的文本相同,不含元数据)。在已加载游戏时,于任何页面按 `j` 即可在 JSON 编辑器中打开面板、切换到它,或在编辑器之外关闭面板。游戏中除 `info` 外的部分起初是折叠的。页面会在你停止输入片刻后随输入而更新,但前提是文本是有效的 JSON 对象,其中有 `info` 对象,且 `info.title` 是文本。否则游戏保持其最后一个有效版本,问题会连同行号和列号显示在编辑器下方。解析器自己的消息仅提供英文。你未完成的文本在切换标签页或关闭面板时会保留,直到你丢弃它或重新加载页面。游戏本身的问题(未知字段、类型错误)只会给出警告:它们会在边栏标出,并列在“问题”标签页和[问题页面](/docs/games/schemas)上,游戏仍会更新。

“格式化”会用 2 个空格缩进重写文本。它仅在 JSON 有效时可用,并且在对象中有重复名称或数字的位数超过可保存范围时会先发出警告,因为这两者都会丢失。末尾的逗号或单引号可以通过边栏中的标记修复。如果游戏在别处被更改(在“更改”页面还原、从历史恢复),文本会随之更新。如果当时你的文本无效,则保持不变,并有提示说明游戏已更改。

在编辑器中 Tab 键用于缩进。要离开编辑器,请按 Escape(第一次 Escape 离开编辑器,第二次关闭面板),然后按 Tab。

#### 编辑器按键

[设置页面](/settings)上的“编辑器按键”设置决定 JSON 编辑器的按键:普通(默认)、Emacs 或 Vim。Emacs 和 Vim 按键在你选择时才会加载,更改设置会保留你的文本及其撤销历史。这些按键仅在编辑器获得焦点时有效。`Mod` 在 macOS 上是 Cmd,在 Windows 和 Linux 上是 Ctrl。在 Emacs 和 Vim 模式下,macOS 上普通按键也可用;在其他系统上,Ctrl 属于该模式。复制、粘贴、撤销和全选在普通模式下保持常用按键。在 Vim 中,只有处于普通模式且没有待完成命令时,Escape 才会离开编辑器。搜索在 Emacs 和 Vim 中有各自的按键。

| 操作               | 普通                         | Emacs        | Vim        |
| ------------------ | ---------------------------- | ------------ | ---------- |
| 格式化             | `Mod-Shift-f`、`Shift-Alt-f` | `C-c C-f`    | `:format`  |
| 立即用文本更新游戏 | `Mod-s`                      | `C-x C-s`    | `:w`       |
| 下一个问题         | `F8`                         | `M-g n`      | `]d`       |
| 上一个问题         | `Shift-F8`                   | `M-g p`      | `[d`       |
| 搜索               | `Mod-f`                      | `C-s`、`C-r` | `/`、`?`   |
| 下一个匹配         | `Mod-g`                      |              |            |
| 上一个匹配         | `Shift-Mod-g`                |              |            |
| 全部折叠或展开     | `Ctrl-Alt-[`、`Ctrl-Alt-]`   |              | `zM`、`zR` |

### 指向编辑器某一部分的链接

页面的地址会记录你所在的位置,因此可以分享或以后再回来:章节(`/games/18Test/tiles`)、打开的面板及其标签页(`?edit=true&editSection=json`、`?config=true&section=tokens`)以及卡牌筛选(`?hidePrivates=true`)。不存在的标签页或章节名称会打开第一个。

在 JSON 编辑器中,点击行号即可标记该行。按住 Shift 点击会标记从第一个已标记行到所点击行之间的所有行;按住 Cmd 点击(Windows 和 Linux 上为 Ctrl)会添加或移除一行,同时按住 Shift 则添加该范围。已标记的行以 `lines` 出现在地址中,例如 `?edit=true&editSection=json&lines=1-4,15,16,19`,打开链接时编辑器会滚动到第一行。标记行不会在浏览器历史中增加页面。切换标签页或关闭面板后,这些行会被忘记。

## 更改、保存和历史

当已加载的游戏与其文件不同时,游戏菜单(以及工具栏)中会出现“更改”条目,并显示已更改的顶层字段数量。它会打开一个页面,用高亮的差异显示游戏与文件(加载时或上次保存时的状态)的对比。差异按缩进为 2 个空格的 JSON 进行比较,因此文件中仅有空白不同的地方不会显示。

在“更改”页面上,“保存”会把游戏写入其文件,内容与“下载”按钮相同,因此第一次保存可能会重新格式化文件。“还原为已保存的版本”会丢弃更改。保存适用于应用中的游戏、在支持的浏览器中从文件系统打开的游戏(浏览器会请求写入权限),以及浏览器私有文件系统中的游戏。内置游戏没有文件,不能被覆盖保存:请使用“另存为...”保存副本,或下载。如果文件在加载之后在 18xx Maker 之外被修改,在你选择重新加载(丢失你的更改)或覆盖之前,不会写入任何内容。

本次会话中的每次保存都会列在“历史”页面上:即该次保存之前的文件。“查看差异”会将其与游戏当前状态比较,“恢复”会把它放回作为你未保存的更改。加载其他游戏或刷新页面后,历史不会保留。未保存的更改同样不会保留:关闭或刷新页面之前,浏览器会先询问。
