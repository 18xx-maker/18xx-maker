# 文件

18xx Maker 使用了许多不同的浏览器技术来处理文件,这可能会让人困惑。本页将帮助您理清其中的情况。

## 内置游戏

18xx Maker 的应用和网页中预先打包了许多 json 文件。例如 [Shikoku 1889](/games/1889/map) 和 [The Old Prince 1871](/games/TheOldPrince1871/map)。这些游戏始终列在[加载游戏](/games)页面上。您可以通过游戏信息页面上的“下载”(网站)或“保存”(应用)按钮下载 json,了解这些游戏是如何构建的。

若要检查游戏文件是否有错误,请运行 `pnpm maker validate my-game.json`(它会根据游戏模式校验文件,参见 [JSON 模式](/docs/games/schemas))。

## 使用 18xx Maker 应用

使用应用时,18xx Maker 可以访问您的文件系统,这意味着您可以从电脑加载 JSON 文件。您可以通过几种方式打开游戏文件:

1. 使用“打开”菜单选项,并选择一个有效的 JSON 文件
1. 在应用中的任意位置按“o”键
1. 点击[加载游戏](/games)页面上的“打开文件”按钮。
1. 将有效的 JSON 文件拖入应用窗口

无论哪种方式,应用都会把该文件的位置保存在其记忆中,然后显示游戏。此后您会在[加载游戏](/games)页面上看到该文件。此页面上的垃圾桶图标**不会**删除文件,而是删除应用对该文件的记忆,该条目会从页面上消失。

如果您在电脑上移动了文件,然后试图点击[加载游戏](/games)页面上的条目来加载它,应用会告知您找不到该游戏,并从页面上移除该条目。

加载游戏后(无论通过上述哪种打开方式,或点击之前打开过的文件的条目),应用会从文件系统加载最新版本,并开始监视该文件。所做的任何更改都应几乎即时地反映在应用中。

## 使用 18xx Maker 网站

网站版 18xx Maker 的行为会因您的浏览器是否支持[文件系统 API](https://developer.mozilla.org/zh-CN/docs/Web/API/File_System_API) 而略有不同。

### 支持的浏览器

您可以通过几种方式从电脑加载文件:

1. 在应用中的任意位置按“o”键
1. 点击[加载游戏](/games)页面上的“打开文件”按钮。
1. 将有效的 JSON 文件拖入浏览器窗口

无论哪种方式,浏览器都会把该文件的位置保存在其记忆中,然后显示游戏。此后您会在[加载游戏](/games)页面上看到该文件。此页面上的垃圾桶图标**不会**删除文件,而是删除浏览器对该文件的记忆,该条目会从页面上消失。

以后再次访问该网页时,当您尝试从[加载游戏](/games)页面加载其中某个游戏,浏览器可能会向您请求权限。如果您不授予该文件的权限,它将从此页面移除,但您始终可以通过上述任一方式再次打开它。

如果您在电脑上移动了文件,然后试图点击[加载游戏](/games)页面上的条目来加载它,网页会告知您找不到该游戏,并从页面上移除该条目。

浏览器无法监视文件的变化。以这种方式加载文件后,工具栏中会出现“刷新”选项。点击它应当会用本地对文件所做的更改刷新网页。在已从文件系统加载游戏时,您也可以在应用中的任意位置按“r”键刷新。

### 不支持的浏览器

即使您的浏览器不支持文件系统 API,我们也会尝试改用[源私有文件系统](https://developer.mozilla.org/zh-CN/docs/Web/API/File_System_API/Origin_private_file_system)。您可以通过以下两种方式之一打开文件:

1. 点击[加载游戏](/games)页面上的“打开文件”按钮。
1. 将有效的 JSON 文件拖入浏览器窗口

这样做之后,该文件的内容会保存在您本地电脑上一个只有浏览器才能查看的独立位置。游戏会出现在[加载游戏](/games)页面上。点击此页面上的垃圾桶图标**不会**从您的电脑上删除文件,而是让浏览器忘记这个游戏。

要从电脑上的数据刷新文件,唯一的办法是使用上述任一方式重新打开它。

## 导入 config.json

你在[配置面板](?config=true)中更改的设置可以在“数据”部分保存为 `config.json`。要在其他地方应用这样的文件,可以把它拖到应用或网站上,或把内容粘贴到“数据”部分的导入框中。导入的设置将替换你当前的自定义设置。如果拖入的 JSON 文件只包含配置设置,它会被当作配置处理,否则会作为游戏加载。

## 编辑游戏信息

在游戏的编辑页面上,工具栏中的“编辑”按钮(或 `e` 键)会在页面旁打开一个面板,其中有游戏信息、链接以及原型和制作中标记的表单。页面保持可见,并随你的输入而更新。该表单由[游戏文件模式](/docs/games/schemas)生成,因此模式中这些部分新增的字段会直接出现在面板中,无需修改应用。字段名称和说明来自模式,仅提供英文。离开字段或按回车键时,值会被应用;清空字段会将其从游戏中移除(标题不能被移除)。值的问题,例如缺少 `#` 的货币,会显示在字段下方。按 Escape 关闭面板(JSON 编辑器见下文)。

面板为它编辑的游戏的每个部分提供一个标签页。按 `[` 和 `]` 在它们之间切换(数字键会跳转到游戏的其他部分并关闭面板)。列车标签页为游戏的每辆列车提供一张卡片,由同一份模式生成。用“添加列车”添加列车,并用卡片上的按钮上移、下移、复制或删除它。删除后可以立即用“撤销”恢复。不常用的列车字段在“更多字段”下。模式中标记为已弃用的字段仍可编辑,并会显示警告。

私有公司标签页以同样的方式编辑游戏的私有公司。卡片首先显示名称、价格、收益、公司、备注和说明。收益是一个数字,或按打印方式书写的列表,如 `10/20`;不是数字的文本(如 `$10/$20`)保持为文本。私有公司的能力以 JSON 编辑,其他字段在“更多字段”下。

市场标签页编辑股票市场:类型(2D、1D 或 1Diag)、单元格网格、单元格默认值、图例和移动。点击单元格,或用方向键移动,即可在网格下方的表单中编辑它:数值、标签、颜色、图例项、发行价标记、箭头等。Delete 清空单元格,数字键跳到其数值。网格上方的按钮可为所选单元格所在的行或列添加、移动、复制和删除;删除的行或列可用“撤销”恢复。市场常常是三角形,因此各行长度可以不同,且不会被补齐。1Diag 市场分两行绘制,一列是两个单元格。只有数值或只有标签的单元格会保存为该数字或文字,设置第二个字段后才变成对象。把类型改为 1D 或 1Diag 时只保留第一行,并可撤销。图例项按编号使用:移动或删除某一项时会显示有多少单元格现在指向另一项,它们的编号不会被修改。显示、ledges、limits 和标题是“高级”下的 JSON 字段。

编辑内容保留在已加载的游戏中。请在下文所述的“更改”页面查看并保存。

### JSON 编辑器

JSON 标签页以 JSON 编辑整个游戏(与“下载”按钮写入的文本相同,不含元数据)。按 `j` 在此标签页打开面板、切换到该标签页,或在编辑器之外关闭面板。页面会在你停止输入片刻后随输入而更新,但前提是文本是有效的 JSON 对象,其中有 `info` 对象,且 `info.title` 是文本。否则游戏保持其最后一个有效版本,问题会连同行号和列号显示在编辑器下方。解析器自己的消息仅提供英文。你未完成的文本在切换标签页或关闭面板时会保留,直到你丢弃它或重新加载页面。游戏本身的问题(未知字段、类型错误)只会给出警告:它们会在边栏标出,并列在[问题页面](/docs/games/schemas)上,游戏仍会更新。

“格式化”会用 2 个空格缩进重写文本。它仅在 JSON 有效时可用,并且在对象中有重复名称或数字的位数超过可保存范围时会先发出警告,因为这两者都会丢失。末尾的逗号或单引号可以通过边栏中的标记修复。如果游戏在别处被更改(在“更改”页面还原、从历史恢复),文本会随之更新。如果当时你的文本无效,则保持不变,并有提示说明游戏已更改。

在编辑器中 Tab 键用于缩进。要离开编辑器,请按 Escape(第一次 Escape 离开编辑器,第二次关闭面板),然后按 Tab。

## 更改、保存和历史

当已加载的游戏与其文件不同时,游戏菜单(以及工具栏)中会出现“更改”条目,并显示已更改的顶层字段数量。它会打开一个页面,用高亮的差异显示游戏与文件(加载时或上次保存时的状态)的对比。差异按缩进为 2 个空格的 JSON 进行比较,因此文件中仅有空白不同的地方不会显示。

在“更改”页面上,“保存”会把游戏写入其文件,内容与“下载”按钮相同,因此第一次保存可能会重新格式化文件。“还原为已保存的版本”会丢弃更改。保存适用于应用中的游戏、在支持的浏览器中从文件系统打开的游戏(浏览器会请求写入权限),以及浏览器私有文件系统中的游戏。内置游戏只能下载。如果文件在加载之后在 18xx Maker 之外被修改,在你选择重新加载(丢失你的更改)或覆盖之前,不会写入任何内容。

本次会话中的每次保存都会列在“历史”页面上:即该次保存之前的文件。“查看差异”会将其与游戏当前状态比较,“恢复”会把它放回作为你未保存的更改。加载其他游戏或刷新页面后,历史不会保留。未保存的更改同样不会保留:关闭或刷新页面之前,浏览器会先询问。
